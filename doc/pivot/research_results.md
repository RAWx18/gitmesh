## 1. GitMesh ground truth [V - live repo, 2026-07-19]

TypeScript 97.6% pnpm monorepo: `cli/`, `lib/`, `server/`, `ui/`, `skills/`, `playbooks/`, `agents/triage/`, `docker/`, `governance/`. Positioning: "Policy-as-Code Engine for Open Source AI Agent Orchestration" - multi-agent runtime (Triage/PR-Review/Docs/Security/Community/Onboarding/Release), heartbeat scheduling, governed MCP server, ACP orchestrator (JSON-RPC 2.0), YAML→Rego via OPA, GitHub/GitLab webhook sync, budgets, immutable audit log, embedded PostgreSQL (Drizzle, `~/.gitmesh-agents/`), dashboard. 142★ / 47 forks / 597 commits; v0.4.0-alpha (2026-01-19); npm `gitmesh-agents`; Apache-2.0; OpenSSF Silver; LFDT Lab; two maintainers; DCO; weekly call. Five adoption cliffs (server, DB, webhooks, agents.yaml, MCP endpoint) before value. The repo itself carries AGENTS.md, CLAUDE.md, and `.claude/skills/` side by side - the maintainers already live the fragmentation problem.

## 2. Standards layer [V]

- **AAIF** formed 2025-12-09 under the Linux Foundation; Platinum members Amazon, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft, OpenAI; founding project donations: MCP (Anthropic), AGENTS.md (OpenAI), goose (Block). Per the AAIF announcement, AGENTS.md is adopted by 60,000+ open-source projects and read natively by Amp, Codex, Cursor, Devin, Factory, Gemini CLI, GitHub Copilot, Jules, VS Code, and more.
- **AGENTS.md is instruction-only by design**: it deliberately does not cover permissions, hooks, or sandboxing; no AAIF cross-agent *enforcement* standard exists; and a dedicated cycle-3 search found **no official AAIF/LF validation CLI**. (An AAIF "v1.0 + validation tooling" roadmap item remains [I], single secondary source.)
- **MCP:** 10,000+ servers; ~100M+ monthly SDK downloads [V-1]; Enterprise-Managed Authorization stable Jul 2026 [V-1]; **SEP-1766** proposes digest-pinned tool versioning in the spec (proposed, not adopted).
- **Agent Skills:** spec at agentskills.io (Anthropic, 2025-12-18); ~30–40 compatible products by mid-2026 [V-1]. Distribution: Vercel `skills` CLI + skills.sh directory - ~4,257 skills growing ~147/day per cycle-3 direct check (a cycle-2 "89k+" figure conflicts; likely installs/scrape conflation - adopt ~4.3k); openai/skills curated catalog.
- **ACP** (Zed): editor↔agent JSON-RPC transport, **not a config standard**; the ACP Registry (with JetBrains) distributes agents, not policies; external agents keep their native config. Confirms no cross-agent permission registry exists.
- **Agent Trace** (emerging, Git AI-led): attribution spec implemented by Git AI, Cline, and OpenCode - the format `gitmesh receipt` should consume.

## 5. Config-sync/converter census - 15+ tools, saturated [V]

**Leaders:** **Ruler** (intellectronica; ~2.6k★/137 forks; npm @intellectronica/ruler v0.3.44): `.ruler/` source + ruler.toml → 30+ agents; rules + MCP + skills + subagents; copy-based generation (atomic replace); `revert`; gitignore automation; documented CI-diff pattern; explicit "skipped with a warning" for agents lacking a primitive. **rulesync** (dyoshikawa): `.rulesync/` source; `generate` / `import` / direct `convert --from X --to Y`; rules/ignore/MCP/commands/subagents/hooks per-tool with an explicit support matrix and **lossy-projection notes** (e.g., Kiro IDE-vs-CLI split); `fetch` config packs.

**The "agentsync" cluster and kin (five projects share the name):** **spxrogers/agentsync**: 31 agents, 9 deep adapters (v0.1.0 beta); detailed lossy-projection reporting ("never silently" drops; remaps hook events; documents what Codex loses from Claude subagents). **baranovxyz/agentsync**: `.agents/agentsync.toml`; presets via `github:org/standards`; profiles (frontend/backend/ci); monorepo overrides; `doctor`/`clean`. **dallay/agentsync**: Rust, **symlink-based**; `doctor`; skills install/update/uninstall; MCP generation; gitignore reconciliation. **yelmuratoff/agent_sync**: `.ai/src/` → 11 tools; `check` and `doctor` catch a forgotten manifest commit before merge and detect manual edits to generated files (`--force` to overwrite). **claaslange/agentsync**: Liquid-templated single source with per-target variables. **GowayLee/agent-sync**: OCaml symlinker (one AGENT_GUIDE.md → CLAUDE.md/GEMINI.md/…). **PanisHandsome/ai-rules-sync**: zero-dep normalized-IR converter; `sync --check|--watch|--auto` with `.agentsync-state.json`; `lint`; web playground.

**Other approaches:** **snapsynapse/agentlink** (agentlink.run) - Go, pure symlinks, no codegen; `detect`/`scan`/`doctor`/`hooks install`; scans `~/Git` for AGENTS.md repos and wires symlinks; refuses to overwrite real files. **dot-agents** (dot-agents.com) - "AGENTS.md v2": `~/.agents/` hierarchy, symlinks, task tracking, hooks management. **vibe-rules** (npm) - `~/.vibe-rules/` store; save/load/convert across ~12 tools; installs rules exported by npm packages. **airul** (mitkury) - generates AGENTS.md/CLAUDE.md *from your docs*. **agent-kit**: generates configs from one AGENTS.md and mirrors `node_modules` packages' `skills/` folders into each agent dir (collision-proof flattening). **anywhere-agents** (yzhao062) - opinionated *published config*: SessionStart auto-bootstrap; PreToolUse guard denying `.md` writes containing ~45 banned "AI-tell" words; destructive-command guard (enforcement-via-hooks UX worth studying). **ai-config-sync-manager** (community, May 2026): `~/.claude` ↔ `~/.codex` diff/plan/apply/backup incl. **permissions**: user-scope, two tools.

**Category-wide gaps (every one of them):** no cross-tool risk audit (secrets in MCP config, bypass modes, unpinned skills); no whole-workspace drift semantics (the doctors that exist check only their own generated outputs); no policy compilation into native enforcement; no org-managed-surface emission; no unified lockfile; no receipts. **Verdict: saturated and commoditizing - interoperate and move up-stack; never market as the 16th sync tool.**

## 7. Permission / policy / hooks tooling - the moat check [V]

- **ZacheryGlass/agent-sync**: the only tool found translating *permissions* across tools: Claude `settings.json` allow/ask/deny ↔ VS Code Copilot boolean auto-approve flags (`settings.perm.json`-style); bidirectional, stateful, **lossy** (VS Code has no hard deny → downgraded to "require approval" with a warning); ~3★; 2 tools; Codex/Gemini "coming soon" unimplemented. A translator, not a compile-from-canonical-policy system. Top watch item alongside amtiYo.
- **PromptArmor**: commercial consulting that designs hardened **Claude and Codex** policies with one-click downloads. Proof of willingness-to-pay; a service, not an OSS compiler with a coverage matrix.
- **managed-settings.com**: web toggles → Claude-only managed-settings JSON.
- **Hooks ecosystem (Claude-centric):** SDKs - cchooks (Python, 123★), cc-hooks-ts (35★), claude-hooks-sdk (PHP, 62★), claude_hooks (Ruby, 36★), syou6162/cchook (YAML config); managers - claude-hooks CLI (73★; doctor/init/enable/disable), Hookify (natural-language hook creation); collections - karanb192/claude-code-hooks (installable marketplace; safety/cost/observability; includes a **pr-provenance-stamp** hook writing provenance into PR bodies - receipts-adjacent), disler/claude-code-hooks-mastery, JalelTounsi's 30-hook security set (secret scanning + destructive-command blocking); **weykon/agent-hooks** (Rust) registers one bridge command into *each* tool's hooks for event **capture**, not policy.
- **Native org-managed surfaces with no OSS compiler:** Claude managed-settings.json (+`.d`, policyHelper, MDM/console); Codex requirements.toml (+execpolicy `.rules`); Antigravity allowed/denied commands. 2026 hardening guides still instruct hand-mapping one policy per tool.
- **Verdict:** compile-one-policy → N native enforcement configs (repo tier) + org-managed artifacts (org tier) with a generated coverage matrix remains **empty**. Nearest neighbors: a 3-star 2-tool translator and a consulting service.

## 11. Net verdict - corrected occupied/contested/open map, and the ten lessons

**Occupied:** harnesses & meta-harnesses; fleet orchestration; config *generation/sync* (15+ tools); skills distribution (Vercel); MCP/skill *content* security scanning (Snyk, Cisco); per-surface pinning (mcp-lock, skills-lock); line-level attribution (Git AI + Agent Trace); runtime agent governance (funded startups); enterprise forge-side control (Agent HQ).
**Contested:** audit/doctor - single-tool and single-file incumbents including first-party `/checkup`; CI drift only as `--check` subcommands and an MCP-only Action.
**Open (confirmed by dedicated searches):** cross-tool workspace doctor with drift semantics; a first-class cross-tool CI drift gate + unified interoperating lockfile; **policy compiled to native enforcement across agents, repo tier + org-managed tier, with a generated coverage matrix** (nearest neighbors: a ~3★ two-tool translator and a consulting service); DSSE/in-toto-signed **workspace-state receipts** consuming Agent Trace.

**Ten lessons applied to `pivot.md`:** (1) don't build the 16th generator - move up-stack (→ §7 positioning). (2) Cross-tool breadth is the differentiator; every incumbent doctor is single-tool (→ §8.1, T1.19). (3) "Never silently drop" honesty is a feature - coverage matrix + lossy-projection reporting (→ §10.6, E4 ACs). (4) Enforcement compilation is empty; ship it and there is no direct competitor (→ §8.4, E7). (5) Lockfiles are validated but scoped; unify and interoperate (→ Δ3, T5.3/T5.4). (6) Consume Git AI/Agent Trace, never rebuild attribution (→ §8.5). (7) Org policy files are hand-written everywhere; compile managed-settings + requirements.toml as the enterprise on-ramp (→ T7.9/T7.10). (8) #6235 is a free marketing tailwind (→ launch kit). (9) Interoperate to win migrations - import competitors' sources (→ §8.2, T3.10/T3.11, T2.5). (10) Timing: a vendor shipped single-tool audit 11 days ago; regulatory/enterprise attention rewards build-time evidence - speed to the policy moat is the key variable (→ §13, CT1/CT2).
